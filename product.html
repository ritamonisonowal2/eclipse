Explainable checks

The four checks behind every score

Every evaluation executes four independent computer vision check modules.

VAL-01

Document Validation

Confirms the image behaves like an authentic identity document: aspect ratio within ID-band width, sharp focus, realistic OCR word density, and plausible metadata signatures.

Inputs: aspect ratio • Laplacian blur • OCR word count • EXIF data

TAM-02

Tampering Analysis

Scans for digital alterations: Error Level Analysis (ELA) re-save compression hotspots, copy-move pixel cloning, and localized sharpness inconsistencies across document surfaces.

Inputs: ELA blocks • copy-move similarity • blur heterogeneity

FAC-03

Face Verification

Processes document portrait and live selfie photos through FaceRecognitionNet, generates 128-D vector embeddings, calculates Euclidean distance, and verifies blink liveness.

Inputs: 128-D embeddings • Euclidean vector distance • blink liveness

CON-04

Data Consistency

Parses extracted dates of birth, issue/expiration windows, document ID patterns, and standard field labels, evaluating them against mathematical validation rules.

Inputs: date parser • ID pattern matcher • field labels • checksums

Risk model

Weighted fusion, fully explained

Each module produces a confidence trust score (0–100). The final risk score is 100 − weighted trust, and the decision action follows defined thresholds.

Check Module Weight Evaluation Factors
Document Validation 30% Aspect ratio • Focus quality • OCR word volume
Tampering Analysis 30% Error-level re-save • Pixel cloning • Regional blur
Face Verification 25% Face presence • Vector embedding match • Liveness
Data Consistency 15% Date logic • ID pattern syntax • Checksum coherence
Risk Score Formula 100 − (0.30×DV + 0.30×TA + 0.25×FV + 0.15×DC)
LOW RISK (0–39)

AUTO CLEAR

All check signals are robust and within expected variance. Document passes automated verification immediately.

MEDIUM RISK (40–69)

MANUAL REVIEW

One or more check signals indicate potential anomalies. Routed to a human compliance specialist for inspection.

HIGH RISK (70–100)

SECONDARY VERIFICATION

High probability of document editing, tampering, or face mismatch. Escalated immediately for secondary identity verification.

Privacy & security

Your images never leave the device

The ECLIPSE VERIFY engine executes 100% inside the user's web browser using WebGL and WebAssembly. Image preprocessing, OCR, forensics, and biometric face comparison happen locally — zero uploads to external servers.

  • ✓ Client-side WebAssembly analysis pipeline
  • ✓ Zero image storage or remote data retention
  • ✓ Local neural OCR engine with offline capabilities
  • ✓ Transparent, explainable risk score breakdown
